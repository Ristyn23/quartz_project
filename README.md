# Work With Quartz (Fiji Plugin)

## Требования

Для разработки и запуска проекта необходимы:
1. **JDK 11** (например, Oracle OpenJDK 11.0.x). Использование JDK 17, 21 или 27 приведет к ошибкам совместимости с библиотеками SciJava/ImageJ2.
2. **IntelliJ IDEA** (Community или Ultimate Edition).
3. **Git**.
4. **Maven** (встроенный в IntelliJ IDEA или установленный в системе).

## Архитектура проекта

Архитектура плагина построена на принципах разделения ответственности (Separation of Concerns) и адаптированной под экосистему SciJava версии паттерна MVC (Model-View-Controller). Главная цель — изолировать математическую логику обработки изображений от пользовательского интерфейса и фреймворка Fiji, что упрощает тестирование и поддержку кода.

### Структура пакетов

* **`istu.quartz.app`**  
  Точка входа исключительно для локальной разработки и тестирования. Содержит класс `RunFiji`, который инициализирует контекст ImageJ и запускает графический интерфейс. В итоговый JAR-файл плагина этот код не влияет на работу в самом Fiji.

* **`istu.quartz.commands` (Controller)**  
  Содержит классы, реализующие интерфейс `org.scijava.command.Command`. Это "контроллеры" или точки входа плагина.  
  *Задачи:*
    - Регистрация плагина в системе через аннотацию `@Plugin`.
    - Получение входных данных от пользователя через аннотации `@Parameter` (Fiji автоматически генерирует на их основе диалоговые окна).
    - Координация работы: передача данных в слой алгоритмов и вывод результатов.

* **`istu.quartz.model` (Model - Данные)**  
  Содержит классы, описывающие предметную область (Domain Model). Это обычные Java-объекты, не зависящие от UI.  


* **`istu.quartz.view` (View)**  
  Содержит кастомные классы пользовательского интерфейса (например, наследники `JPanel` или `JDialog` из Swing).

### Поток данных (Data Flow)

1. Пользователь выбирает плагин в меню Fiji (`Plugins` -> `Analyze Quartz`).
2. SciJava создает экземпляр класса из пакета `commands` и отображает диалоговое окно (View), сформированное на основе его полей `@Parameter`.
3. Пользователь выбирает изображение и настраивает параметры, затем нажимает `OK`.
4. Метод `run()` в классе-команде (Controller) извлекает эти данные.
5. Контроллер передает изображение и параметры в класс из пакета `algorithm`.
6. Алгоритм обрабатывает изображение и возвращает объект результата (Model).
7. Контроллер принимает результат и отображает его: выводит статистику в `LogService`, рисует области интереса (ROI) на изображении или сохраняет данные в файл.

### Используемые паттерны и механизмы

* **Command Pattern:** Реализован нативно через интерфейс `org.scijava.command.Command`.
* **Dependency Injection (Внедрение зависимостей):** SciJava автоматически внедряет необходимые сервисы (например, `LogService`, `DatasetService`, `DisplayService`) в поля контроллера, помеченные аннотацией `@Parameter`, без необходимости создавать их вручную через `new`.
* **Plugin Discovery:** Механизм сканирования аннотаций `@Plugin` во время запуска, позволяющий Fiji динамически находить и регистрировать новые команды.
