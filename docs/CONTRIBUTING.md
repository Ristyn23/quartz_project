## Требования к окружению

Для разработки и тестирования плагина необходимы:

| Компонент | Версия                                   | Примечания                                                    |
| ------------------ | ---------------------------------------------- | ----------------------------------------------------------------------- |
| JDK                | 11 (Oracle OpenJDK 11.0.x или аналог) | JDK 17+ несовместим с SciJava/ImageJ2                       |
| Apache Maven       | 3.6+                                           | Для управления зависимостями и сборки  |
| IntelliJ IDEA      | Community или Ultimate                      | Рекомендуется для разработки                  |
| Fiji (ImageJ)      | Актуальная версия              | Для тестирования собранного артефакта |
| Git                | Любая актуальная версия   | Для контроля версий                                    |

Использование JDK 17 или выше приведёт к ошибкам на уровне модульной системы и библиотек SciJava. Убедитесь, что в настройках проекта и IDE указан JDK 11.

## Локальная разработка

### Импорт проекта в IntelliJ IDEA

1. Откройте IntelliJ IDEA и выберите `File › Open`.
2. Укажите путь к корневой директории репозитория `quartz_project`.
3. IntelliJ автоматически импортирует Maven-проект и загрузит зависимости.
4. Убедитесь, что в `File › Project Structure › Project SDK` выбран JDK 11.

### Запуск плагина в режиме разработки

Для локального тестирования без необходимости развёртывания в Fiji используйте класс `RunFiji`:

1. Откройте файл `src/main/java/istu/quartz/app/RunFiji.java`.
2. Запустите метод `main()` через контекстное меню (`Run 'RunFiji.main()'`).
3. Откроется окно Fiji с загруженным плагином.
4. Плагин доступен через меню:
   - `Plugins › Quartz Segmentation › Analyze Quartz` — основной анализ зёрен.
   - `Plugins › Quartz Segmentation › Merge Images…` — совмещение нескольких снимков.

Класс `RunFiji` используется исключительно для локальной разработки. В итоговый `.jar`-файл плагина он не влияет.

### Сборка артефакта

Для создания дистрибутива выполните:

```bash
mvn clean package
```

Результат — файл `target/quartz_project-1.0-SNAPSHOT.jar`.

Для тестирования собранного артефакта:

1. Скопируйте `.jar` в директорию `plugins/` вашей локальной установки Fiji.
2. Перезапустите Fiji.
3. Проверьте работу плагина через меню `Plugins › Quartz Segmentation`.

## Тестирование новых функций

### Совмещение снимков StackMerger

Для тестирования функционала совмещения нескольких перекрывающихся снимков:

1. Подготовьте 2–5 изображений одной области образца с частичным перекрытием.
2. Все изображения должны быть одинакового размера и в формате RGB.
3. Запустите `Merge Images…` из меню Fiji.
4. Добавьте снимки в порядке съёмки.
5. Нажмите `Совместить` для выполнения SIFT-регистрации.
6. Проверьте результат на вкладке `Проверка совмещения` с помощью слайдера прозрачности.
7. Нажмите `Объединить` для усреднения RGB-каналов.
8. При необходимости выделите область интереса (прямоугольник с поворотом или полигон).
9. Сохраните результат в TIFF или передайте в основное окно анализа.

Ожидаемое поведение:

- Алгоритм должен корректно регистрировать кадры даже при изменении освещённости.
- RANSAC-фильтрация должна отбрасывать выбросы сопоставления признаков.
- Усреднение должно учитывать только валидные пиксели.

### Физический масштаб SpatialScale

Для тестирования калибровки изображения:

1. Загрузите изображение в основное окно анализа.
2. Нажмите `Задать по двум точкам…` в панели `Масштаб`.
3. Укажите два конца отрезка известной длины на изображении.
4. Введите реальное расстояние и единицу измерения (мкм, мм, см, м).
5. Проверьте, что на изображении появилась линейка масштаба.
6. Выполните анализ и экспортируйте CSV — должны появиться калиброванные колонки:
   - `length_unit`, `pixel_size`
   - `area_calibrated`, `perimeter_calibrated`, `equivalent_diameter_calibrated`
   - `major_axis_calibrated`, `minor_axis_calibrated`

Ожидаемое поведение:

- Масштаб должен сохраняться в метаданных TIFF.
- При загрузке TIFF масштаб должен автоматически восстанавливаться.
- Калиброванные значения должны корректно вычисляться из пиксельных метрик.

### Маска области анализа AnalysisRegion

Для тестирования ограничения области анализа:

1. Загрузите изображение с маской области (TIFF с встроенной маской в `Info`).
2. Маска должна отображаться как шахматный паттерн на превью.
3. Выполните анализ — watershed должен игнорировать пиксели вне маски.
4. Проверьте, что в карте меток нет зёрен за пределами маски.

Ожидаемое поведение:

- Маска должна встраиваться в TIFF как Base64-кодированный PNG.
- При сохранении разметки маска должна сохраняться вместе с ней.
- Метод `GrainLabelMap.restrictTo()` должен корректно обнулять метки вне маски.

### Сохранение и загрузка разметки GrainAnnotationIO

Для тестирования сохранения промежуточной разметки:

1. Выполните анализ и ручную коррекцию зёрен.
2. Нажмите `Сохранить разметку…`.
3. Выберите формат:
   - TIFF — карта меток как числовое изображение.
   - ROI ZIP — набор ROI-объектов Fiji.
4. Закройте окно и откройте его заново.
5. Загрузите исходное изображение.
6. Нажмите `Открыть разметку…` и выберите сохранённый файл.
7. Проверьте, что разметка восстановлена корректно.

Ожидаемое поведение:

- TIFF-формат должен сохранять масштаб в метаданных.
- ROI ZIP должен содержать файл `quartz.properties` с метаданными.
- Валидация при загрузке должна проверять размеры, корректность ID, отсутствие пересечений.
- Атомарная запись должна гарантировать целостность файла при сбоях.

### Выделение области интереса SelectionImages

Для тестирования кадрирования объединённого снимка:

1. Совместите несколько снимков в `Merge Images…`.
2. Перейдите на вкладку `Объединённый снимок`.
3. Выберите режим выделения:
   - Прямоугольник - поддержка поворота, drag-resize, drag-move.
   - Многоугольник - клик для добавления вершины, Enter/двойной клик для замыкания, Delete для удаления вершины.
4. Выделите область интереса.
5. Нажмите `Использовать в Quartz` или `Сохранить TIFF…`.

Ожидаемое поведение:

- Извлечение должно выполняться с билинейной интерполяцией.
- Маска выделения должна сохраняться в `AnalysisRegion`.
- Физический масштаб должен переноситься из исходного изображения.

## Процесс внесения изменений

### Стиль кода

- Язык: Java 11.
- Форматирование: отступы — 4 пробела. Используйте автоматическое форматирование IDE.
- Именование:
  - Классы: `CamelCase` (например, `GrainLabelMap`)
  - Методы и переменные: `camelCase` (например, `areaInPixels`)
  - Константы: `UPPER_SNAKE_CASE` (например, `BOUNDARY_CLASS`)
- Комментарии: пишите комментарии на русском языке. Для публичных API используйте Javadoc.

### Требования к Pull Request

3. Изменения протестированы локально:

   - Запустите плагин через `RunFiji.java`.
   - Проверьте все затронутые функции на реальных данных.
   - Для новых функций следуйте инструкциям из раздела `Тестирование новых функций`.
4. Документация обновлена:

   - Если изменено поведение плагина, обновите `docs/USER_GUIDE.md`.
   - Если изменена архитектура, обновите `docs/ARCHITECTURE.md`.
   - Если изменён формат выходных данных, обновите `docs/DATA_SPEC.md`.
5. Коммиты оформлены согласно Conventional Commits:

   - `feat:` — новая функциональность
   - `fix:` — исправление ошибки
   - `docs:` — изменения в документации
   - `refactor:` — рефакторинг
   - `test:` — добавление тестов

### Ревью кода

- Pull Request должен быть проверен минимум одним другим разработчиком.
- Все замечания должны быть устранены перед слиянием.
- После слияния ветка удаляется.
