# Архитектура проекта Quartz Analysis Plugin

## Обзор

Проект реализует конвейер обработки микроскопических изображений кварца с использованием адаптированного паттерна Model-View-Controller в рамках экосистемы SciJava/ImageJ2. Архитектура построена на принципе строгого разделения ответственности: математическая логика обработки изображений изолирована от пользовательского интерфейса и фреймворка Fiji, что обеспечивает тестируемость и возможность повторного использования алгоритмов вне контекста плагина.

## Структура пакетов

### `istu.quartz.commands` (Controller Layer)

Пакет содержит классы, реализующие интерфейс `org.scijava.command.Command`. Эти классы выполняют роль точек входа и координаторов:

- Регистрация в системе плагинов осуществляется через аннотацию `@Plugin(type = Command.class, menuPath = "...")`. Механизм сканирования аннотаций SciJava позволяет Fiji динамически обнаруживать команды без явной регистрации в конфигурационных файлах.
- Поля, помеченные аннотацией `@Parameter`, заполняются контейнером SciJava автоматически. Это избавляет от необходимости создавать экземпляры сервисов `LogService`, `DatasetService`, `DisplayService` вручную через конструкторы или фабрики.
  Команды не содержат бизнес-логики. Их единственная задача — инициализировать пользовательский интерфейс и передать ему управление.

Такой подход соответствует рекомендациям SciJava по разработке плагинов и минимизирует связность между фреймворком и предметной логикой.

### `istu.quartz.model` (Domain Layer)

Ядро предметной области. Классы этого пакета не имеют зависимостей от Swing, SciJava UI или Fiji. Они работают исключительно с примитивами ImageJ `ImagePlus`, `ImageProcessor` и библиотеками обработки изображений.

#### `GrainBoundarySegmenter`

Инкапсулирует взаимодействие с библиотекой Trainable Weka Segmentation. Отвечает за:

- Загрузку обученной модели классификации из файла `.model`.
- Применение классификатора к входному изображению.
- Извлечение карты вероятностей для класса границ зерен.

Класс ожидает, что в модели существует класс с точным именем `grain_boundary`. Это жесткое требование, обусловленное отсутствием механизма автоматического определения целевого класса в API TWS.

#### `GrainWatershed`

Реализует алгоритм водораздельного преобразования для разделения слипшихся зерен:

- Применяет гауссово размытие к карте вероятностей границ для подавления шума.
- Квантует значения в диапазон `byte` (0-255) для совместимости с алгоритмом watershed.
- Вызывает `ExtendedMinimaWatershed` из MorphoLibJ с параметрами: толерантность 20, связность 4.

Ручная реализация гауссова фильтра (метод `smoothAndQuantize`) вместо использования `ij.plugin.filter.GaussianBlur` обусловлена необходимостью точного контроля над edge padding (используется nearest-pixel) и последующим квантованием. Стандартный фильтр ImageJ не предоставляет достаточной гибкости для этого пайплайна.

#### `GrainLabelMap`

Центральная структура данных, представляющая карту меток зерен. Хранит массив `float[]`, где каждый пиксель содержит ID зерна (0 — фон).

**Ключевые операции**:

- `merge(int first, int second)` объединяет два зерна в одно. Алгоритм проверяет, что зерна соседствуют (имеют общие граничные пиксели), и переназначает все пиксели второго зерна и пиксели фона между ними в ID первого зерна.
- `split(int grain, List<Point> stroke)` Разделяет зерно по нарисованной пользователем линии. Алгоритм:
  1. Создает бинарную маску зерна.
  2. Рисует линию разделения на маске.
  3. Выполняет компонентный анализ `BinaryImages.componentsLabeling`.
  4. Проверяет, что линия делит зерно ровно на 2 части.
  5. Присваивает новый ID меньшей компоненте, сохраняя ID большей.

Метод `areaInPixels(int label)` имеет сложность O(W×H), так как выполняет линейный проход по всему массиву пикселей. Для изображений высокого разрешения это может вызвать задержки при частых вызовах из UI. Рекомендуется кэширование площадей или использование гистограмм.

#### `GrainMeasurement`

Вычисляет морфометрические характеристики зерен с использованием MorphoLibJ:

- Площадь (в пикселях).
- Периметр (алгоритм Кротона с 4 направлениями).
- Эквивалентный диаметр.
- Оси эквивалентного эллипса.
- Коэффициенты формы aspect ratio, circularity, roundness.

MorphoLibJ предоставляет проверенные реализации алгоритмов морфометрии, соответствующие стандартам стереологии. Ручная реализация потребовала бы значительных усилий по валидации и тестированию.

#### `GrainCsvExporter`

Отвечает за сериализацию измерений в формат CSV. Использует атомарную запись через временный файл с последующим перемещением `StandardCopyOption.ATOMIC_MOVE`, что гарантирует целостность данных при сбоях во время записи.

### `istu.quartz.ui` (View Layer)

Реализация пользовательского интерфейса на базе Swing. Ключевые особенности:

#### Многопоточность

Все тяжелые операции выполняются в `SwingWorker`. Это предотвращает блокировку Event Dispatch Thread (EDT) и сохраняет отзывчивость интерфейса. Промежуточные результаты публикуются через механизм `publish()`/`process()`, обеспечивая визуальную обратную связь.

#### `ImagePreview`

Кастомный компонент для отображения изображений с поддержкой:

- Масштабирования с фокусом на курсоре мыши `zoomAtCursor`.
- Преобразования координат экрана в координаты изображения `imagePoint`.
- Наложения полупрозрачных слоев для визуализации границ и выделения зерен.

Зум реализован через изменение логических координат центра изображения `centerX`, `centerY` и пересчет видимой области. Это позволяет избежать накопления ошибок округления при многократном масштабировании.

#### `GrainEditorPanel`

Интерактивный редактор карты меток. Поддерживает:

- Выделение зерен кликом мыши.
- Режим разделения линией - рисование с зажатой кнопкой мыши.
- Отображение морфометрических данных для выбранных зерен в реальном времени.

Перерисовка overlay выполняется только при изменении состояния, а не при каждом движении мыши. Это снижает нагрузку на CPU при работе с большими изображениями.
